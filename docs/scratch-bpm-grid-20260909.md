# スクラッチ・BPM・解析グリッドの整備

## 原因と変更

- DDJ-1000 の再生中ジョグ補正は `setTempo` で `rate_ratio` を一時変更していた。新しい `deck.pitchbend` は Mixxx の `wheel` に音声速度補正を送り、テンポフェーダーと BPM を変更しない。150ms のネイティブ側タイムアウトで補正を解除し、ロード・アンロード・スクラッチ開始でも解除する。旧ホストへの互換経路は残すため、エンジンの再起動が必要。
- タッチ中の側面入力も、開始済みスクラッチの移動として処理する。テンポ変更へ混入させない。
- スクラッチの位置追従がパケット到着時刻の揺れを音声速度へ強く反映していた。速度予測は維持し、位置誤差の補正ゲインを 0.25 → 0.08、出力速度に 10ms の平滑化を追加。停止・解放時の処理と感度設定は維持する。
- 解析済みの検出拍をすべて可変テンポとして再生していた。新規解析では生の検出拍とは別に `features_extra.playback_grid` とそのバージョンを保存する。再生・波形・同期には同じグリッドを渡す。
- 16 拍以上について全曲の一次回帰を行い、残差の 95% が 20ms 以内、最大が 50ms 以内の場合だけ一定テンポとする。丸めない BPM と開始位置を保存する。条件に合わないものは検出拍を保持する。小節頭の検出精度を改善したものではない。
- 旧解析データにも同じ整形を適用できる。解析キャッシュはバージョンを分離し、リズム再解析時に古い候補を無効化する。リズム解析バージョンは v3。
- rekordbox から取り込んだグリッドとユーザー保存済みグリッドは自動整形しない。保存済みの解析グリッドを更新する場合は、グリッド編集から解析候補を選び直して保存する。

## 検証範囲

- ネイティブテスト：速度補正が実音声クロックへ作用し、自動解除されること、補正・逆回転中も 120 BPM／rate=1／グリッド開始位置を維持すること。不正値・別トラックへの補正を拒否すること。
- スクラッチ音声テスト：微小移動、一定速度、入力間隔がばらつく逆回転、停止・解放・古いジェスチャー・タイムアウト。
- Python：一定テンポの検出揺れと長時間の丸め誤差、実際のテンポ変化、欠落拍、解析グリッドの保存データからの読み出し、既存のグリッド優先順位。
- DDJ-1000 の実機での最終的な操作感、実楽曲すべての拍検出精度は未検証。再生時のリアルタイム再解析を導入したものではない。

今回の音声テストでは一定速度入力の局所的な速度変動指標が 0.0622 → 0.0009。微小移動の停止コールバックは 0/138、入力間隔を揺らした逆回転の最低速度／平均速度は 0.979。これは合成入力と Mac スピーカー出力でのテスト値で、実機操作の誤差率ではない。Python 43 件、Node 114 件、ネイティブのスクラッチ音声テストが通過。

反映にはアプリ／バックエンドの再起動とトラックの再ロードが必要。既存ライブラリ全体の再解析は実行していない。
