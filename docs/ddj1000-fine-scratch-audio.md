# 細かいスクラッチ入力の断続音修正

2026-09-09。ジョグ移動量0.10 ms/countは維持し、ネイティブ音声側を修正。

`ScratchDeck`は回転中にも1msの位置デッドバンドを適用していた。
0.4msずつ20ms間隔の連続入力で、148音声コールバック中120回が速度ゼロとなることを既存バイナリで再現した。
小さい移動が蓄積するまで停止し、その後追従する処理が断続音の原因になる。

回転中はデッドバンドを適用せず、位置追従のゲインを0.25に統一。
30ms以上移動がなく目標との誤差が1ms未満のときは、従来どおり停止して静止時の振動を抑える。
ジョグ入力の感度、Mixxx上流コード、アートワークは変更していない。

検証:

- 微小連続入力で速度ゼロの割合が10%未満である回帰テストを追加。旧バイナリで失敗、修正ビルドで成功。
- ネイティブスクラッチテスト成功。48kHzモノラル音源から録音した前進・後退PCM、静止時の無音、解放、ジェスチャ競合、watchdogを確認。
- ネイティブDDJ-1000統合テスト成功。Node回帰テスト111件成功。

実機での聴感やrekordboxとの比較測定は未実施。稼働中の旧ホストは自動終了させず、アプリ再起動で更新する。

## 追記: スクラッチ中の速度リップル（2026-09-09 同日）

実機で「低音のキレが悪い、グジュグジュする」との指摘。原因は帯域ではなく、
位置追従則が**階段状の目標を P 制御だけで追っていた**ことだった。

`scratch2` へ渡すレートは `0.25 * 位置誤差 / 1バッファ` で、目標 `samples_` は
入力パケットが届いたときにしか動かない。パケット間（数十ms）は誤差が
1 コールバック（5.805ms）ごとに 25% ずつ減るので、レートはパケット到着で
跳ね上がり次の到着まで減衰する鋸歯になる。入力間隔の周期で速度が変調される
＝ 全パーシャルに側帯波が付き、低音の輪郭が消える。

BlackHole 2ch にホストを立て、`DJALY_MIXXX_TIMING_TRACE=1` のコールバック単位
トレースで実測（一定速度の連続入力、5点移動平均からのずれ／平均速度）:

| 入力間隔・速度 | 修正前 | 修正後 |
| --- | --- | --- |
| 10ms・1.0倍 | 5.20% | 0.32% |
| 20ms・1.0倍 | 19.47% | 0.15% |
| 10ms・0.3倍 | 5.06% | 0.18% |
| 10ms・ベビースクラッチ（正弦往復1.6倍） | 6.47% | 2.51% |

反転時のピーク速度も 1.85 → 1.76 倍（理想 1.60）へ改善した。三角波の瞬間反転で
測ると修正後のほうが行き過ぎるが、手もジョグも瞬間反転しないため、有限加速度の
正弦で評価している。

### 修正

1. 位置入力が届いた実時刻の差から手の速度を推定する（一次平滑、係数 0.5）。
   ハートビートは位置を変えないので間隔に混ぜない。120ms を超える間隔は
   速度とみなさず推定を捨てる。`requestedAt_` はトレース無効でも常に記録する。
2. パケットの谷間は、その速度で目標を外挿して連続にし、同じ速度を送り項にも
   足して追従遅れを消す。時間軸はコールバック数ではなく実時刻で測る
   （5.805ms 刻みでは入力間隔と位相が合わず段差が残る）。入力が途切れたら
   1 入力間隔ぶんかけて外挿を 0 へ戻す。
3. 解放時、外挿で先に出た距離が 1 バッファの権限（±16 倍）を超えると着地
   レートが上限に張り付いて戻し切れず、6 倍速・16ms 入力で 85ms の着地ずれが
   出た。権限を超える場合だけ上限レートのまま 1 バッファ持ち越し、権限内に
   入ってから既存の着地計算に渡す。

### 検討して採らなかった案

- 追従ゲインを上げる: 階段を追う P 項のリップルは `ゲイン × 速度 × 入力間隔 /
  バッファ長` なので、ゲインを上げるとリップルは増える。
- α-β トラッカー（タイムスタンプ不使用）: オフライン比較で定常リップルが
  2.5〜18% 残り、外挿方式（ほぼ 0）に劣る。
- 外挿量に距離上限を置く: 上限に当たると目標が止まる一方で送り項が押し続け、
  かえって大きく振動した（実測 roughness 5.2% → 14.9%）。
- 目標を最新観測で頭打ちにする補間: コールバック量子化で目標が観測へ早着し、
  次のパケットまで停滞して鋸歯が復活した（同 18.1%）。
- 解放レートのスルーレート制限: 補正が遅れて誤差が増え、着地が悪化した。

### 検証

- 回帰テストを `scratch.test.mjs` に追加（`steady-motion`）。10ms 間隔・等速
  1.0 倍の連続入力で、コールバック速度のがたつきが 2% 未満であることを見る。
  旧バイナリでは 5.78% で失敗し、修正ビルドでは 0.26〜0.38% で成功する。
- ネイティブテスト 15 ファイル全件成功（scratch / timing / seek-drag /
  negative-position / ddj1000 / protocol / dj-controls / beatgrid /
  variable-beatgrid / first-fx / beat-fx-audio / colorfx-audio / sampler /
  sampler-audio / recording-finalization）。Node 回帰テスト 113 件成功。
- `timing.test.mjs` の解放 7 試行はすべて着地誤差 6.1ms 以内、
  コマンド受信〜通常速度復帰 22.6ms 以内（予算 30ms）、PCM の隣接段差 0.41ms 以内。
- 実機での聴感確認は未実施。`stage/DJalyMixxxHost.app` を更新済みなので、
  反映にはアプリの再起動が必要。

## 追記2: 入力間隔が延びたときの音切れ（2026-09-09 同日）

実機で「一定速度でバックスピンすると無音になる」「スクラッチで音が途切れる」との
指摘。上のリップルと同じ根（階段目標を P 制御だけで追う）から出る、より重い症状
だった。パケットが来ない間は誤差が 1 コールバックごとに 25% 減るので、入力間隔が
コールバック数個ぶんを超えると**プラッターがパケット間で止まる**。

修正前バイナリでの実測（一定速度 -6 倍の逆回転、レート最小値 ÷ 平均）:

| 位置更新の間隔 | 修正前 | 修正後 |
| --- | --- | --- |
| 10ms | 0.822 | 0.983 |
| 25ms | 0.524 | 0.936 |
| 40ms | 0.245 | 0.982 |
| 60ms | 0.112 | 0.797 |
| 5〜70ms のジッタ | **0.041** | **0.895** |

録音 PCM の最小レベルも、ジッタ条件で 974 → 2108（平均 2121）になった。40ms 以上
または不規則な間隔になると、旧実装は指示速度の 4〜25% まで落ちる＝ほぼ停止する。
UI スレッドが詰まって位置更新が遅れるだけでこの状態になる。

### 追加した対策

1. 外挿（上記）により、パケットの谷間も推定速度で目標が進み続ける。これが主因の解消。
2. 無音デッドバンドの条件に「手が実際に止まっている」を追加した。従来は
   `位置更新が 30ms 途切れ && 誤差 1ms 未満` だけでレートを 0 にしていたため、
   手は回っているのに UI が詰まっただけで音が切れ得た。推定速度が 0.02 倍未満の
   ときだけ黙る。
3. 入力間隔の推定を「伸びに即応・縮みはゆっくり」にした。ジッタで急に間隔が
   伸びたとき、外挿が谷間の途中で切れて音が痩せるのを防ぐ。
4. 位置が変わらない入力が届いたら手が止まったとみなし、外挿を 1 パケットあたり
   0.35 倍で素早く畳む。入力そのものが途切れている場合（UI が詰まっただけ）とは
   区別し、そちらは繋ぎ続ける。

`scratch.test.mjs` に回帰テスト `jitter-spin` を追加。5〜70ms のジッタで -6 倍の
逆回転を送り、レートが平均の 50% を下回らないことを見る（修正前 0.041、修正後
0.876〜0.896）。

ネイティブテスト 15 ファイル全件成功、Node 回帰テスト 113 件成功。実機での聴感確認は未実施。
