# バックスピンの無音・スクラッチの粗さの追跡

## 今回修正したもの

`Ddj1000Runtime` は移動中も 200ms ごとに同じ位置を保持通知として送信していた。ネイティブの速度推定は位置の変わらない入力を停止と解釈し、推定速度を 0.35 倍にする。このため移動の途中へ不要な減速が入る可能性があった。

直近 200ms にジョグ移動があれば保持通知を送信しない。静止して押さえている間の保持通知と 1500ms のネイティブ安全解除は維持する。動作中の重複通知がなく、静止中は通知を続ける回帰テストを追加。Node 115 件と UI ビルドが通過。

## 無音症状の検証状況

`native/mixxx-engine-host/tests/backspin-audio.test.mjs` を追加。48kHz の音源を Mac スピーカー出力で逆再生して録音し、6x・12x・16x で各 20ms 窓に無音がないことを検査。すべて通過し、16-bit PCM の最低 RMS はそれぞれ約 1412、1413、1413。

このテストはファイルの中央から始める合成入力であり、実機の無音症状を再現したものではない。タッチ解除、ファイル先頭を越えた逆回転、実際のミキサー／FX 状態を原因から除外できない。DDJ-1000 は OS 上で接続を確認したが、読み取り専用の生 MIDI 記録では今回の操作入力を得られていない。保持通知修正だけで無音症状が解決したとは判断していない。

追加確認：ユーザー報告は「高速で逆回転している間」の無音。`DJALY_SCRATCH_CODEC=mp3` / `m4a` で同じテストを行い、両形式とも 6x・12x・16x の連続逆再生に無音区間はなかった。合成信号・曲途中・独立した初期ミキサー状態での結果に限る。追加した60秒の実機モニターも入力0件だったため、実機の再生位置・停止状態との照合は未完了。

ユーザーから無音中も波形は動き続けると確認。`DJALY_SCRATCH_LONG=1 DJALY_SCRATCH_CODEC=mp3` で5分のMP3の別々の位置を読み出すテストも通過した。

## 操作後に読める自動診断

診断版エンジンは、スクラッチ時だけ `/tmp/djaly-scratch-<エンジンPID>.json`（macOSではシステムの一時ディレクトリ）へ最大40回分の状態を上書き保存する。250ms間隔でメモリに状態を集め、全デッキのスクラッチを離した後にファイルへ保存する。操作中にディスク同期で入力処理を遅らせない。音声サンプルや曲名・ファイルパスは記録しない。ファイルは所有ユーザーのみ読み書き可能。

- `positionMs`、`durationMs`：ファイル範囲内か、先頭より前へ逆回転したか。
- `speed`、`inputAgeMs`：音声側が受け取った速度と入力の鮮度。
- `preFaderPeak`：デッキの音量補正・デッキ内FXを通った後、チャンネルフェーダーへ入る前のピーク。
- `silentMovingBuffers`：速度の絶対値が0.1超なのにデッキ信号がほぼゼロだったバッファ数（累積）。曲の無音部分も数えるため、これだけで不具合とは判断しない。
- `masterPeak` と `mixer`：その後の出力メーターとミキサー・FX設定。

音声スレッドでは固定数のアトミック値のみ更新し、ファイル操作・JSON生成はしない。テストで、音の出ている逆回転と、意図的にファイル先頭より前へ戻した無音の両方が診断に残ることを確認した。無音の原因そのものはまだ未確定。

## 実機の記録を踏まえた継続処理の修正

PID 708 の実機記録では、Deck A のテンポ倍率は全15サンプルで1、移動中のデッキ無音バッファ数は0。約 -4.57／-4.65 倍の逆再生の直後に `scratching=false`、速度1へ戻る区間があった。記録は250ms単位のため、タッチセンサーの生バイトや解除の意図までは断定できない。

コントローラー側の実装はタッチOFFですぐにジェスチャーを終了し、その後の回転入力をテンポ補正へ切り替えていた。高速逆回転（推定速度 -0.75 倍未満）直後のタッチOFFでは、最大60msの入力待ちを設ける。負方向の回転入力が続けば実際の移動量だけ追従し、入力が60ms途切れれば終了する。再接触では同じジェスチャーを保ち、正方向への切り替え・VINYL OFF・通常の静止解放では持ち越さない。人工的な慣性は加えない。

MIDI→デコーダー→ランタイム→コマンドキュー→実エンジンのテストで、タッチOFF後も回転パケットが続く間は逆再生と音声信号が続き、テンポ倍率は1、入力終了後は解除されることを確認。

ジョグのHID画面とMIDI BPM表示は、PC画面と同じ「保存された解析BPM × テンポ倍率」を優先するよう統一。解析BPMがない場合だけネイティブの局所BPMを使用する。

診断の `masterPeak` は参照キーを `[Main]/vu_meter` に修正。以前の `[Master]/vu_meter` は存在しないキーだったため、PID 708 の masterPeak=0 をマスター音声が無音だった根拠には使わない。今後の記録には局所 `effectiveBpm` も含める。
