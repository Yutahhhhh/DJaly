# DDJ-1000 BEAT FX 実装確認（2026-09-09）

## 不反応の原因

公式MIDI表のセレクターは14位置だが、ランタイムの対応表は6位置のみだった。
他の8位置では `mixer.beatfx.set {enabled:false}` を送り、以降のON操作も抑制していた。
ECHOだけの録音検証では、この実装漏れを検出できなかった。
またMASTERの経路が録音・配信・モニターへの分岐より後の `[MasterOutput]` だった。
共通の `[Master]` へ変更し、MASTER指定の録音にもFXが入るようにした。
これはソースとテストで確認した原因であり、今回ユーザーが操作した実機の生バイトを捕捉した結果ではない。

## 全14位置の対応

基準は提供された [公式表の転記](ddj1000-midi-map.md)。以下のNOTEはch5（status `94`）。

| NOTE | 刻印 | 音声処理 |
| --- | --- | --- |
| 20 | LOW CUT ECHO | 250Hz以下を減衰させた信号のフィードバックディレイ |
| 21 | ECHO | Mixxx Echo |
| 22 | MT DELAY | 3タップ・左右交差ディレイ |
| 23 | SPIRAL | 読み出し時間を変調するフィードバックディレイ |
| 24 | REVERB | Mixxx Reverb |
| 25 | TRANS | Mixxx Tremoloの矩形波設定 |
| 26 | ENIGMA JET | 2つの遅延読み出しをクロスフェードするジェット処理 |
| 27 | FLANGER | Mixxx Flanger |
| 28 | PHASER | Mixxx Phaser |
| 29 | PITCH | Mixxx PitchShift |
| 2A | SLIP ROLL | 入力を取り込み反復。拍数変更で現在の入力を取り直す |
| 2B | ROLL | ON時の入力を保持して反復。拍数を拡大・縮小可能 |
| 2C | MOBIUS SAW | オクターブを重ねてクロスフェードする鋸歯状波発振 |
| 2D | MOBIUS TRI | 同構造の三角波発振 |

追加8種類はホスト側の独自DSPであり、Pioneerの非公開アルゴリズムや音色の完全再現ではない。
[メーカーの製品説明](https://www.pioneerdj.com/en/product/dj-controllers/ddj-1000/)でも14種類と新規4種類が案内されている。
Mixxx依存リポジトリには変更を加えず、ビルド時にホスト用プロセッサ登録を追加する。

## 操作の確認と追加

- 全14位置を画面とMIDIの共通リストに統一。正規の選択でBEAT FXを強制OFFにしない。
- ON/OFF、LEVEL/DEPTH、CH1–4 / MASTER / MIC / SAMPLERの対象指定は既存コマンド経路を使用。
- SHIFT＋BEAT左のAUTO、SHIFT＋BEAT右のTAPはデコード後に未処理だったため追加。直近最大4間隔の平均から40–300 BPMを設定。AUTOでソースの拍情報に戻る。
- 手動BPMは全プロセッサの音声入力メタデータに適用。曲の再生速度や解析BPM自体は変更しない。
- MASTER / MICなど曲の拍情報を持たない経路のAUTOは、同期マスターデッキ、再生中の先頭デッキ、120 BPMの順で参照する。
- 追加DSPおよびECHOの拍数は現実装で1/8–2、TRANSは1/8–4に制限し、画面・MIDIの上限を揃える。メーカーの全パラメーター範囲を再現したものではない。
- 各追加DSPの遅延メモリは音声スレッド外で確保。ON時はカウンターで古いデータを無効化し、音声コールバックで大きなメモリ確保や消去をしない。

## 検証

- Node回帰テスト113件。全14セレクターの生MIDI列、ON/OFFの押下と解放、TAPの120 BPM算出、AUTO復帰を含む。
- 全14種類を同一ホストで順に選択し、ルート・チェーン有効・スロット有効・手動BPM伝播・AUTO復帰を確認。
- 80 / 1000 / 8000Hzと無音区間を含む音源を録音し、14種類すべてで乾いた音との差を確認。ECHO初回ON、RELEASE、ノブ変更後の再発動、MASTERの録音への反映も検証。
- Playwrightで14選択肢、MASTER指定、ON/OFF、BPM入力、AUTO操作を確認。
- 合成音源による機能テストであり、全種類の実機聴感、原機との音色一致、全対象の実音ルーティングを測定したという意味ではない。

ネイティブホストの更新はアプリ再起動で反映する。
